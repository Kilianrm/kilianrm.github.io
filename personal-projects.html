CV MATCH In progress

A SaaS platform matching job seekers with relevant opportunities

CV Match is a SaaS platform that helps people find jobs suited to their experience and goals. Users create a candidate profile by uploading a CV or entering their details manually. The platform gathers job listings from external platforms and matches those opportunities to each profile. It also offers AI-powered CV tailoring for selected roles and sends notifications when relevant opportunities are found.

A microservices architecture separates profile management, CV parsing, job collection, matching and notifications. Each capability can evolve and scale independently as demand grows, supporting the scalability and resilience expected of a large SaaS platform.

Key technical work:

  • Designed service boundaries and asynchronous workflows so independently deployable capabilities can scale according to their workloads.
  • Gateway Service: implemented a FastAPI entry point with JWT verification, session handling and routes for profile, CV and catalog operations.
  • Profile Service: built PostgreSQL-backed profile management for skills, roles, experience, education and certifications, plus CV upload and deletion with S3-compatible storage.
  • CV Parser Service: scaffolded the FastAPI service and wired its local configuration to a dedicated SQS queue, dead-letter queue, CV storage and Profile Service.
  • Job Scraper Service: documented a source-centric ingestion design and normalized job-listing contract for external platforms.
  • Matching Service: designed user- and system-scoped matching flows, ranked results and events for newly discovered matches.
  • Notification Service: designed preference-aware email digests triggered by new matches and scheduled delivery windows.
  • CV Optimizer: captured role-specific, AI-powered CV tailoring as a distinct product capability.
  • Infrastructure as code: authored modular AWS CDK stacks in TypeScript for networking, security, compute, data, authentication, Gateway and Profile services.
  • CI/CD and deployment: automated frontend lint and build checks with GitHub Actions, and created Make/script workflows for local stacks and AWS CDK deployments.
  • Testing: added unit and component tests for Gateway and Profile, parser health checks, and positive/negative cross-service coverage for authentication, profile and CV workflows.

EVENT PLATFORM SERVICE

Serverless Cloud-Native Event Ingestion Platform (AWS)

Cloud-native event platform built on AWS to simulate an internal event ingestion and retrieval system. It is designed around a serverless, event-driven architecture where events are ingested via API Gateway, processed asynchronously, and persisted for later retrieval. The system emphasizes scalability, reliability, and clean architectural boundaries, applying real-world cloud design practices.

The architecture is built using AWS Lambda, API Gateway, DynamoDB, and SQS to enable fully decoupled asynchronous processing. It includes DLQ-based fault tolerance, JWT-based authentication for secure access, and CloudWatch observability for monitoring and tracing event flows. The system is designed to handle failures gracefully while maintaining data consistency and traceability across the pipeline.

Infrastructure is fully provisioned using Terraform, ensuring reproducible and consistent deployments across environments. The project also includes unit, integration, and end-to-end testing to validate both application logic and infrastructure behavior.

Key technical work:

  • Designed and implemented a serverless event-driven architecture using AWS Lambda, API Gateway, DynamoDB, and SQS.
  • Implemented asynchronous event processing with queue-based decoupling and DLQ-based fault tolerance.
  • Developed JWT-based authentication using Lambda authorizers to secure API endpoints.
  • Provisioned infrastructure using Terraform following Infrastructure as Code best practices.
  • Implemented observability and monitoring using AWS CloudWatch (logs and metrics).
  • Developed Python-based Lambda functions for event ingestion, validation, and processing pipelines.
  • Built unit, integration, and end-to-end tests for backend and infrastructure validation.
AWS Lambda API Gateway DynamoDB SQS DLQ Terraform Python JWT CloudWatch Serverless

KUBE COST WORKSPACE In progress

Kubernetes Cost and Capacity Desktop Workspace (Go)

Local desktop app for understanding and reducing Kubernetes cost. It estimates what a Deployment manifest will cost before it is deployed, shows what a connected cluster runs and what it bills, and builds a costed plan to cut that bill. It connects with the user's own kubeconfig or AWS CLI session, never stores credentials, and never changes the cluster: every suggested change is a command the user reviews and runs.

The app is built in Go and packaged as a desktop application with Wails. All cost logic lives in a pure Go core with no Kubernetes, cloud SDK or I/O dependencies, so the desktop app and the kubeestimate CLI share one cost model. Nodes are priced from AWS, Google Cloud and Azure list prices by machine type, region and on-demand or spot purchase option.

Cluster data comes from the Kubernetes API, metrics-server and the Amazon EKS API. Cost is split into billed, allocated and idle capacity, with budget forecasting and an optimization plan covering rightsizing, node removal, better machine types, spot migration and orphaned volumes. The project includes unit tests across the core and adapters, plus scripted demo clusters on kind and on EKS with eksctl.

Key technical work:

  • Designed a layered architecture with a pure Go cost core shared by the desktop app and the CLI.
  • Built a manifest converter and cost engine that price Deployments per container and per resource across AWS, GCP and Azure.
  • Implemented a Kubernetes collector with metrics-server usage and direct Amazon EKS connection through the AWS CLI.
  • Modeled billed vs allocated vs idle cost by namespace, workload and node group, with history trends.
  • Built budget forecasting with month-end projection and a breakdown of what changed between periods.
  • Created an optimization planner shown as a savings waterfall, with risk notes, ready-to-run commands and apply/confirm tracking.
  • Simulated manifest rollouts against the live cluster to show whether new nodes are needed and how the bill changes.
